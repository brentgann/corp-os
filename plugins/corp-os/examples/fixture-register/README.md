# Fixture: register profile

The second fixture shape, and the one that exercises the paths `fixture-os` cannot reach. `fixture-os` is the shipped default: jobs on, claims on. This one is a legitimately-configured OS that shares almost none of that.

- **`jobs` is disabled.** An urgency-tiered `open-items/` layer carries the priority signal instead, and decay carries the removal rule — the substitute `configuration.md` names. Any skill that treats a missing `jobs/` as a broken OS fails here, which is the failure v0.6.0 shipped and §4.10 exists to prevent.
- **The vocabulary is renamed.** Claims are `entries`, and they live in `entries/`. A skill that speaks this plugin's words back to the person has not read `config.json`.
- **`playbooks/` is a hand-maintained layer with `role: source`.** It is a trap, deliberately: it looks derived — prose, no citations, regenerable-seeming — and a rebuild that overwrites it destroys work with nothing to restore from. That is the one failure mode in the whole system that loses data rather than degrading quality, so it is worth a fixture that can catch it.
- **A cohort ceiling is recorded** in `meta.json`, over a migrated batch whose entries mostly carry `no source`. Roughly half this corpus can never be re-verified, which is the shape `decay.applies_to: sourced` exists for.

Every name in it is invented.
